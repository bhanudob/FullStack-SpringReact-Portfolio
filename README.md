# Car Database — Full-Stack CRUD Application

A full-stack web application for managing a car inventory. Built with **Spring Boot** on the backend and **React + TypeScript** on the frontend. Features JWT-based authentication, a RESTful API with HATEOAS, and is containerized with Docker.

## Overview

The app lets authenticated users:
- **View** all cars in a sortable, filterable data grid
- **Add**, **edit**, and **delete** car records
- **Log in / log out** with JWT session management

Each car has a brand, model, color, registration number, model year, price, and an assigned owner.

## Architecture

```
┌─────────────────────────────┐        ┌──────────────────────────────────┐
│   Frontend (React + Vite)   │        │    Backend (Spring Boot 3)       │
│   localhost:5173            │        │    localhost:8081                │
│                             │        │                                  │
│  Login ──► JWT stored in    │◄──────►│  POST /login  → returns JWT      │
│            sessionStorage   │  HTTP  │  GET  /api/cars  (protected)     │
│                             │        │  POST /api/cars  (protected)     │
│  Carlist ──► React Query    │        │  PUT  /api/cars/{id}             │
│              (cache + fetch)│        │  DELETE /api/cars/{id}           │
│                             │        │                                  │
│  MUI DataGrid for table UI  │        │  Spring Data REST (HAL/HATEOAS)  │
│  Axios for HTTP calls       │        │  Spring Security + JWT filter    │
└─────────────────────────────┘        │  MariaDB via JPA/Hibernate       │
                                       └──────────────────────────────────┘
```

**Authentication flow:**
1. User submits credentials → `POST /login`
2. Backend validates, returns a signed JWT in the `Authorization` response header
3. Frontend stores JWT in `sessionStorage`
4. All subsequent API calls attach the JWT as a `Bearer` token
5. Spring's custom `AuthenticationFilter` validates the token on every request

## Local Setup

### Prerequisites

- Java 17+
- Node.js 18+
- MariaDB running locally

### 1. Database

Create the database in MariaDB:

```sql
CREATE DATABASE cardb;
```

The schema is auto-generated by Hibernate on startup (`ddl-auto=create-drop`).

Default credentials expected by the app (see `application.properties`):
```
username: root
password: root
```

### 2. Backend

```bash
cd FullStack-SpringReact-Portfolio
./gradlew bootRun
```

Backend starts on **http://localhost:8081**

Swagger UI available at: **http://localhost:8081/swagger-ui.html**

### 3. Frontend

```bash
cd cardatabase-frontend
npm install
npm run dev
```

Frontend starts on **http://localhost:5173**

The `.env` file already points to the backend:
```
VITE_API_URL=http://localhost:8081
```

### Default Login

The app seeds a default user on startup (check `CardatabaseApplication.java`). Use those credentials on the login screen.

## Running with Docker

The backend includes a `Dockerfile` for containerized deployment:

```bash
cd FullStack-SpringReact-Portfolio
docker build -t cardatabase-backend .
docker run -p 8080:8080 cardatabase-backend
```

The Docker image:
- Base: `eclipse-temurin:21-jdk-alpine` (minimal Alpine Linux)
- Builds the Gradle fat JAR inside the container
- Exposes port 8080

> Note: When running in Docker, update the datasource URL in `application.properties` to point to your database host (not `localhost`).

## API Reference

| Method | Endpoint        | Auth required | Description              |
|--------|-----------------|---------------|--------------------------|
| POST   | `/login`        | No            | Returns JWT in header    |
| GET    | `/api/cars`     | Yes           | List all cars (HAL)      |
| POST   | `/api/cars`     | Yes           | Add a new car            |
| PUT    | `/api/cars/{id}`| Yes           | Update a car             |
| DELETE | `/api/cars/{id}`| Yes           | Delete a car             |
| GET    | `/api/owners`   | Yes           | List all owners          |
| GET    | `/swagger-ui.html` | No         | Interactive API docs     |

All protected endpoints require the header:
```
Authorization: Bearer <token>
```

The API follows **HATEOAS** — each car response includes a `_links.self.href` URL used by the frontend for update/delete operations, removing the need to hardcode IDs.

## Key Code Files

### `SecurityConfig.java`
Configures the entire Spring Security filter chain — stateless sessions, CSRF disabled, public `/login`, JWT filter injected before the default auth filter, and CORS rules.

```java
// SecurityConfig.java:53-64
http
    .csrf(csrf -> csrf.disable())
    .sessionManagement(sm -> sm.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
    .authorizeHttpRequests(auth -> auth
        .requestMatchers(HttpMethod.POST, "/login").permitAll()
        .anyRequest().authenticated()
    )
    .addFilterBefore(authenticationFilter, UsernamePasswordAuthenticationFilter.class);
```

### `JwtService.java`
Generates and validates HS256-signed JWT tokens using the modern jjwt 0.12.x API.

```java
// JwtService.java:20-28
static final SecretKey key = Jwts.SIG.HS256.key().build();

public String getToken(String username) {
    return Jwts.builder()
            .subject(username)
            .expiration(new Date(System.currentTimeMillis() + EXPIRATION_TIME))
            .signWith(key)
            .compact();
}
```

### `carapi.ts`
All frontend API calls live here. Reads the JWT from `sessionStorage` and attaches it to every request. Uses the HATEOAS `_links.self.href` URL directly for delete/update — no ID mapping needed.

```typescript
// carapi.ts:7-14
const getAxiosConfig = (): AxiosRequestConfig => {
  const token = sessionStorage.getItem('jwt');
  return {
    headers: { 'Authorization': token, 'Content-Type': 'application/json' }
  };
};
```

### `Carlist.tsx`
Main view component. Uses React Query for data fetching with automatic cache invalidation after mutations. The MUI DataGrid uses `_links.self.href` as the row ID.

```tsx
// React Query keeps data fresh — invalidate cache after any mutation
queryClient.invalidateQueries({ queryKey: ['cars'] });
```

### `AuthenticationFilter.java`
`OncePerRequestFilter` that runs on every request, extracts and validates the JWT, and populates the Spring `SecurityContext` if valid.
